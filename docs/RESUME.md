## 1. 简历项目条目（四段式）

**项目名称**：基于 STM32F407 的 A/B 双区串口 IAP 升级与回滚系统

**担任角色**：独立开发（Bootloader + 示例应用 + 上位机）

**项目描述**：在 STM32F407VE（512 KB Flash、128 KB 最大扇区）上实现串口 IAP 固件升级。Bootloader 负责启动决策、串口收包、镜像校验与跳转；应用分 A/B 两槽独立链接、原地运行，支持试运行确认与失败自动回滚。使用 C + Keil MDK 开发，裸机驱动 Flash / USART / IWDG，配套 Python + Tkinter 上位机与 ST-Link 一键烧录脚本。

**项目业绩**：

- 实现免搬运 A/B 双区升级：两槽各自链接、原地运行，切换仅改写 96 B 元数据，回滚耗时 < 50 ms。
- 设计 96 B 追加式元数据日志（CRC32 自校验）+ CRC32/SHA-256 双校验；388 个写入断点掉电仿真全部可恢复，实板升级中途断电后旧固件正常启动。
- 实现 TRIAL → CONFIRMED 试运行机制并与 IWDG 联动，新固件 3 次未确认自动回滚；串口分片协议带帧 CRC、ACK 与重传，8 KB 固件升级约 1.8 s。
- 采用 USART 中断接收 + 64 B 环形缓冲，解决 OLED 阻塞刷新期间的串口丢包；实板定位并修复中断未使能、时钟配置错误、栈溢出、Flash 擦除超时等 6 个问题。

**技术栈**：C / Cortex-M4 / STM32F4 寄存器编程 / Flash 驱动 / IWDG / UART 协议 / Python / Tkinter / OpenOCD / Keil MDK

## 4. 面试问答（取舍与排查过程在这里讲）

### Q1 为什么不用 MCUboot / WolfBoot？
swap-using-scratch 需要一块 ≥128 KB 的 scratch；512 − 32(boot) − 128 = 352 KB，两个槽各 176 KB，装不下目标 182 KB 应用。
swap-using-move 要求扇区等大，F407 是 16/64/128 KB 混排。
WolfBoot 功能符合但 GPLv3；OpenBLT 没有 A/B 回滚。
自研约 1500 行，逻辑完全可控，也便于在 Keil 下集成。

### Q2 两份固件怎么共存？为什么不拷贝？
direct-xip：每个槽按自己的基址链接（A 0x0800C000 / B 0x08040000），各自原地运行。
拷贝需要第三份空间暂存旧镜像，512 KB 下没有，而且拷贝过程本身有掉电窗口。
切换只改元数据 + VTOR，不搬数据。

### Q3 元数据为什么只追加、不覆盖？
Flash 只能 1→0，改回 1 必须擦扇区（16 KB，约 250 ms）。
覆盖写要擦除，应用确认时会被看门狗复位；追加一条 96 B 只要约 1 ms。
写满 170 条后由 bootloader 在启动阶段整理。

### Q4 写记录到一半断电怎么办？
每条记录带 CRC32；启动扫描时遇到坏记录就停，回退到上一条有效记录。
记录有意义字段都在前 64 B（含 CRC），写到 64 B 即有效。
388 个断点仿真覆盖了这个场景。

### Q5 为什么 trial 是 3 次？
1 次太敏感，一次偶发复位就回滚；10 次会让坏固件反复重启。
3 次能覆盖「一启动就死」和「跑几秒才死」两种情况。

### Q6 怎么证明不会变砖？
逻辑上：旧槽不动 + 记录自校验；仿真上：388 断点；实板上：升级中途拔电，重启仍跑旧固件。
不吹「绝对不变砖」，只说「已验证的断电点均能恢复」。

### Q7 你遇到最难的问题是什么？
OLED 刷新是阻塞的（每帧约 50 ms），应用用轮询收串口，刷屏期间收到的 `boot` 字节被覆盖丢失，表现为「连接时好时坏」。
用 `s_ticks`、USART 状态寄存器、帧缓冲三步定位。
改成 USART 中断接收 + 64 B 环形缓冲后解决。

### Q8 还有哪些不足？
无签名 / 防回滚；单 meta 扇区，整理期间掉电会退一版；只实测 115200；示例应用 8 KB，未在 180 KB 真实应用上验证。

## 7. 项目介绍（约 200 字）

本项目在 STM32F407VE 上实现串口 IAP 固件升级系统：Bootloader 负责启动决策、串口收包、镜像校验与跳转，应用分为 A/B 两个可原地运行的槽位，切换只改写 96 字节元数据，回滚小于 50 ms。元数据采用追加式日志，每条记录自带 CRC32，启动只认最后一条有效记录；镜像使用 CRC32 与 SHA-256 双校验。新固件先进入 TRIAL，应用自检通过后确认，3 次未确认由看门狗联动自动回退。系统附带 Python/Tkinter 上位机与 Keil 双 target 构建，8 KB 固件升级约 1.8 秒，388 个掉电断点仿真全部可恢复。
